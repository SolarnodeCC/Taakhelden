# Web localization (`messages/`, `i18n/`)

## Locales

- Catalogs: `apps/web/messages/nl.json` and `apps/web/messages/en.json`.
- Routing/locale config: `apps/web/i18n/` (`routing.ts`, `request.ts`, `navigation.ts`).
- Add keys to **both** `nl.json` and `en.json` with identical structure.

## Tone

- Parent dashboard strings: clear Dutch (primary) and English.
- Child-facing or kid-notification copy: **positive** framing only — no guilt or pressure
  language (productvoorstel §3.7). Route new kid copy through `@dutch-child-copy`.

## Keys

- Use consistent nested keys per feature (`dashboard.taken.title`, not flat duplicates).
- Do not embed HTML in JSON unless existing patterns already do — prefer plain text.

## i18n code

- Use `next-intl` patterns already in the app; do not bypass locale routing.
- Date/number formatting: locale-aware via next-intl, not manual `toLocaleString` scattered
  in components.

## Verification

- Grep for new UI strings in TSX — each should reference a message key, not hardcoded Dutch.
- `@taakhelden-i18n` for structural i18n changes.
